OpenAgent · UI Direction Study

5 个 UI 方向对比

Apple 极简 · 大留白大标题为共同基调。5 个方向在同一美学家族内， 但结构与交互范式不同 —— 换配色不是方向，换骨架才是。每方向含 Windows 1440×900 与 Android 390×844 两张稿。

方向 01

静默画布 The Quiet Canvas

容器消失，内容成为唯一的界面。没有卡片、没有分区背景、没有阴影 —— 只有排版层次和 1px 发丝线。Agent 的每一类输出（Agent 说话 / 工具调用 / 审批 / 命令） 用左侧一条 2px 色标区分，而不是用气泡。最接近 Apple 原生 App 的气质。

容器消失 排版即分区 单栏 最低视觉噪音
信息架构
扁平。图标轨只承载 6 个一级入口，无二级导航
适合场景
日常文件整理、系统查询、快速问答 —— 高频但轻量
记忆点
Agent 输出流的 2px 来源色标，一眼分清「谁在说话」
风险
没有卡片容器意味着工具日志、协议详情等密集内容无处安放， 需要依赖开发者模式抽屉兜底

方向 02

对话即产品 Conversation Core

Agent 对话是唯一的主界面。720px 居中窄列，其余一切 （设备、任务、工具、Provider）收进右侧可折叠的 Inspector。Command Center 浮层与主窗口 视觉同构 —— 同一个组件，只是尺寸不同。学习成本最低，最贴近文档对 「ChatGPT + Apple」的描述。

单一主界面 居中窄列 上下文可折叠 浮层与主窗同构
信息架构
一层导航（文字式）+ 一层按需展开的 Inspector
适合场景
绝大多数交互 —— 说一句话拿到结果，不关心底层
记忆点
浮层与主窗口是同一个组件的两种尺寸，认知负担几乎为零
风险
与 ChatGPT 的视觉语言高度重合，品牌辨识度最弱； 任务队列、工具注册表等「非对话」内容被压到 Inspector 里会显得局促

方向 03

环境仪表 Ambient Console

先看状态，再下指令。首页是一个纯排版构成的仪表层 —— 超大数字配微小标签， 没有图表卡、没有环形进度条。Agent 输入框常驻底部，随时可打字，像 Spotlight 一样。 匹配「常驻后台的控制中心」这一产品心智。

状态优先 排版化仪表 常驻输入 设备是一等公民
信息架构
带标签侧栏 + 仪表层 + 常驻底栏，三层各司其职
适合场景
长期挂着后台、偶尔瞄一眼状态、随时丢一个任务
记忆点
54px 等宽数字 + 11px 大写标签的仪表排版，不用任何图表
风险
「先看状态」会稀释「Agent 优先」的产品主张； 数字指标天然容易被误读为绝对准确值（文档第 327 条已提醒）

方向 04

工作台 Split Workspace

三栏结构：导航 / 任务流 / 上下文面板。为 Coding Agent 场景优化 —— Working Directory、Git 分支与脏状态、Tool Call 次数、待批准队列常驻右侧，不用切页面。 信息密度最高，但仍靠留白与 1px 发丝线分层，不用满屏卡片。

三栏 上下文常驻 高密度 为 Coding Agent 优化
信息架构
三层并列：一级导航 + 任务流 + 上下文 Inspector
适合场景
长时间盯着的复杂任务 —— 用 Codex / Claude Code 改代码、跑测试
记忆点
右侧 Inspector 把「Agent 正在什么环境下动手」变成常驻可见的事实
风险
与「大留白」的美学要求存在张力；1440 宽度下主区只剩 880px， 再窄就需要折叠 Inspector。文档第 156 条正是这个场景，所以方向本身是对的， 问题是它不该成为唯一形态

方向 05

聚光 Spotlight Primacy

浮层是产品本体，主窗口只是它的展开态。Alt+Space 唤起的 680px 面板不只是输入框，而是完整的任务生命周期容器 —— 输入、计划、审批、流式输出、 结果，全部在浮层内闭环，不跳转、不打断心流。主窗口只在需要长时间观察或管理时才打开。

浮层即产品 零跳转闭环 不打断心流 主窗口次要化
信息架构
浮层（高频全部功能）→ 主窗口（低频管理）两级
适合场景
开发者白天的高频节奏：下任务、审批、看结果，全程不离开当前窗口
记忆点
审批与计划在同一浮层内就地完成，用户视线零位移
风险
与文档第 49 条「主窗口为主体」的描述有偏离，需要产品层接受 「主窗口次要化」；另外浮层承载审批时，误触成本更高，需要把「批准」做成需要 刻意确认的动作

3 套候选色板

三套都基于 OKLCH 构建，中性色带 0.008–0.014 chroma 的品牌色偏移（拒绝死灰）， 各含明暗双主题。用上方的色板切换器可以把上面 10 张稿实时切到任意一套 —— 建议先选色板， 再选方向，因为色板是全局的，方向是结构的。

A · 石墨 Graphite

冷灰偏蓝 + 单一靛青强调色。最耐看，明暗双主题都稳， 与 WinUI 3 的 Fluent 灰阶最接近，落地成本最低。

强调色oklch(52% 0.145 258)
中性偏移hue 250 · C 0.003–0.010
契合品牌Privacy · Control

B · 纸白 Paper

暖灰偏橙 + 低饱和深墨蓝。像印刷油墨落在纸上的感觉， 温度更高，适合强调「本地、离线、属于你自己」。

强调色oklch(40% 0.090 254)
中性偏移hue 70–80 · C 0.004–0.014
契合品牌Local-first · Open

C · 午夜 Midnight

深蓝黑 + 电光青，暗色是第一公民。屏幕感最强， 符合「常驻后台的基础设施」气质；但离常见 AI 配色更近，需要更严格的用色纪律。

契合品牌Cross-device

设计方建议

色板取 A · 石墨，方向取 01 静默画布 为默认形态、 04 工作台 作为 Coding Agent 场景的可切换布局、 05 聚光 作为 Alt+Space 的浮层形态。

理由：三者不是竞争关系，而是同一个产品的三种尺度 —— 静默画布是日常形态， 工作台是复杂任务形态，聚光是瞬时形态。它们共享同一套 token、同一套组件语义， 因此可以共存，且不违反文档第 2 条「不允许为完成第一版而使用阻碍未来扩展的架构」。

02 对话即产品的问题不是不好，而是太容易被误认为是 ChatGPT 客户端； 03 环境仪表的信息架构值得吸收（设备一等公民、状态诚实），但把仪表层做成首页会稀释 「Agent 优先」的产品主张 —— 建议把它的仪表排版并入 01 的 Dashboard。
